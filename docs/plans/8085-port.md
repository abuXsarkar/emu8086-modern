# /8085 — Phased Implementation Plan

A research-grounded plan for adding an Intel 8085 IDE+emulator to the modern8086 monorepo, deployed at `/8085/` under the same domain. Sibling tool, shared chassis, distinct ISA core.

> **Status:** plan only. Phase 1 (skeleton) was partially started — `packages/core-8085/` and `packages/assembler-8085/` Rust stubs exist; everything else is pending.

### 0.2 Canonical dialect spec

The dialect to implement, derived from convergence across GNUSim8085 / Sim8085 / OshonSoft / TASM / A85 / Indian-lab-manual conventions:

1. **Comments:** `;` only, to EOL.
2. **Hex literals:** trailing `H` (case-insensitive), leading `0` **required** when first digit is A–F (e.g. `0FFH`, not `FFH`).
3. **Decimal:** bare digits, optional `D` suffix.
4. **Binary:** trailing `B` suffix.
5. **Octal:** trailing `O` or `Q` (low priority).
6. **Labels:** `IDENT:` — colon required. `[A-Za-z_?@][A-Za-z0-9_?@]*`. Case-insensitive (more forgiving for students).
7. **Mnemonics & registers:** case-insensitive. Reserve `A B C D E H L M SP PSW` from being label names.
8. **Directives:** `ORG`, `EQU`, `DB`, `DW`, `DS`, `END`. Also accept dotted aliases (`.ORG`, etc.) for Oshon paste-in compatibility.
9. **Default ORG when omitted:** `2000H` (matches the 20 ready-to-ship example programs from GeeksforGeeks/Tutorialspoint). Provide a "Lab Kit Mode" preset that switches to `4200H` (Vinytics/Dynalog trainer convention).
10. **Strings (DB):** both `'...'` and `"..."`. Backslash escapes for `\n \r \t \0 \\ \' \"`.
11. **Expressions:** `+ - * /`, parens, `LOW()`, `HIGH()`, location counter `$`. **Standard arithmetic precedence** (not TASM's left-to-right).
12. **One instruction per line.** No multi-statement-per-line, no line continuation.
13. **Newlines:** `\n` and `\r\n` both accepted.
14. **Radix detection:** strictly by suffix. Never treat a leading `0` alone as octal.

### 0.3 Tolerance-mode auto-fixes

Apply silently when the input would otherwise fail. Each fix is reported as a non-blocking inline hint in the editor margin so students learn.

| # | Detected | Auto-fix | Source dialect that motivates it |
|---|---|---|---|
| 1 | Hex `FFH` (starts A–F, no leading `0`) | Prepend `0` → `0FFH` | TASM/Oshon accept; strict assemblers reject |
| 2 | `0xNN` hex | Rewrite to `0NNH` | Oshon / C-trained students |
| 3 | `$NN` hex | Same as #2 | TASM/Oshon |
| 4 | `#NN` immediate prefix | Strip the `#` | ARM/6502 habit |
| 5 | Label without trailing `:` | Insert `:` if line shape is `IDENT INSTRUCTION` | TASM/A85 |
| 6 | Label on its own line above an instruction | Merge as label of next instruction | GNUSim8085 issue #41 |
| 7 | `//` or `#` line comment | Treat as `;` | C/shell habit |
| 8 | `MOV reg, #imm` | Rewrite to `MVI reg, imm` | 6502/ARM habit |
| 9 | Smart quotes from Word/Google Docs | Normalize to ASCII | Lab-manual PDF copy-paste |
| 10 | Leading whitespace before a label | Strip | GNUSim8085 forces col-1 |
| 11 | Trailing `D` on decimal | Strip | Intel-style harmless suffix |
| 12 | `DEFB`/`DEFW`/`DEFS`/`BYTE`/`WORD`/`BLOCK` | Alias to `DB`/`DW`/`DS` | Oshon/TASM |
| 13 | `.ORG`/`.EQU`/`.DB`/`.END` (dot prefix) | Strip the dot | TASM/Oshon |
| 14 | Missing `END` | Insert virtual `END` at EOF, warn only | GNUSim8085-trained students never write it |
| 15 | `ORG` missing | Inject default (`2000H` standard / `4200H` kit-mode) and show in status bar | Indian lab convention |
| 16 | `MOD`/`SHL`/`SHR`/`AND`/`OR`/`XOR`/`NOT` operators | Map to `%`/`<<`/`>>`/`&`/`\|`/`^`/`~` | A85/Intel-manual paste-in |
| 17 | `?` or `@` inside label | Allow (Intel-legal) | A85/sim8085 |
| 18 | UTF-8 BOM at start | Strip silently | Windows Notepad |
| 19 | `_` inside numeric literal (`1010_1100B`) | Strip underscores | Harmless |
| 20 | Mixed-case label resolution (`JZ LOOP` vs `Loop:`) | Resolve case-insensitively, warn | Copy-paste survives |

### 0.4 Top 5 pain points to attack

Ranked by frequency across GitHub issues, Launchpad bugs, vendor changelogs, and review aggregators:

1. **Infinite loops freeze the whole app** (GNUSim8085 #21, Sim8085 #67 went so far as to reject all loops). Fix: Web Worker execution + abort button + cycle budget warning.
2. **Wrong CPU semantics** — DAA, carry propagation, AC flag, DCR after 80H, PSW display, SBB borrow, DAD flag side-effects (GNUSim8085 #71/#46/#14/#45, sim8085 #57/#50/#44/#45/#18, Jubin #17). Fix: comprehensive per-opcode golden test suite (modern8086 has this discipline already; replicate for 8085).
3. **Windows install hell / Java required / no M1 Mac** (Launchpad #680079, GNUSim8085 #50/#65/#13/#25). Fix: web-first inherits the solution.
4. **No share link without paywall** (Sim8085 Plus paywall, multiple cloud-save requests). Fix: free unlimited URL share-link (modern8086 already has it).
5. **No examples library / no inline mnemonic docs / 1998-era UI / no dark mode** (multiple sources). Fix: bundle 20 stock programs + per-mnemonic hover docs + the modern8086 design system.

Secondary pain points (worth addressing but lower priority):
- Memory displayed in decimal while registers in hex (GNUSim8085 #61/#39)
- No interrupt/RIM/SIM/RST support (phoxis review, sim8085 #21, 8085simulator #6/#7)
- Mobile-broken memory cell edit (sim8085 #17)
- Cryptic assembler errors (sim8085 changelog acknowledges this)
- No raw binary export for EPROM burning (sim8085 #77, GNUSim8085 #60)
- No dec/hex/binary converter built-in (sim8085 #46, GNUSim8085 #66)
- No recent-files / file-location memory (GNUSim8085 #55)

## Phase 2: 8085 CPU core M0 — register/flag model

**Goal:** define the 8085 register/flag data model and a `version()` probe. No execution yet.

### What to implement

Copy the M0 pattern from `packages/core/src/cpu.rs` and adapt to 8085's narrower register file.

Module layout in `packages/core-8085/src/`:
- `lib.rs` — re-exports
- `cpu.rs` — `Cpu` struct, register file, flags
- `mem.rs` — `Memory` newtype with 64 KiB addressing (matches 8086's `Memory` pattern but no segmentation)

8085 register file:
- 8-bit registers: A, B, C, D, E, H, L
- Register pairs: BC, DE, HL (the M pseudo-register reads/writes through HL)
- 16-bit: SP (stack pointer), PC (program counter)
- Flag byte: bit 7 S (sign), bit 6 Z (zero), bit 5 0, bit 4 AC (aux carry), bit 3 0, bit 2 P (parity), bit 1 1, bit 0 CY (carry)
- The flag byte packed with A forms PSW for `PUSH PSW`/`POP PSW`

## Phase 4: 8085 core M1 — full ISA decoder + executor + golden test suite

**Goal:** execute every 8085 instruction with bit-exact flag semantics. This is the phase that beats every existing competitor on pain point #2.

### What to implement

In `packages/core-8085/src/cpu.rs`, add:
- `step(&mut self, mem: &mut Memory) -> StepResult` — fetch/decode/execute one instruction
- `run(&mut self, mem: &mut Memory, budget: u64) -> StopReason` — execute until HLT, breakpoint, IO trap, or cycle budget exhausted
- Flag computation helpers: `update_szp(a: u8)`, `compute_ac_add(a, b, cy)`, `compute_ac_sub(a, b, cy)`, etc.

Instruction families to implement (all 246 opcodes):
- Data transfer: MOV, MVI, LXI, LDA, STA, LHLD, SHLD, LDAX, STAX, XCHG
- Arithmetic: ADD, ADC, ADI, ACI, SUB, SBB, SUI, SBI, INR, DCR, INX, DCX, DAD, DAA
- Logical: ANA, ANI, ORA, ORI, XRA, XRI, CMP, CPI, RLC, RRC, RAL, RAR, CMA, CMC, STC
- Branch: JMP + 8 conditionals, CALL + 8 conditionals, RET + 8 conditionals, PCHL, RST 0–7
- Stack/IO: PUSH, POP, XTHL, SPHL, IN, OUT
- Control: HLT, NOP, EI, DI, RIM, SIM

### Golden test suite (critical for pain-point #2)

Write a JSON corpus of `(initial_state, instruction_bytes, final_state)` tuples covering:
- Every opcode at least once
- Every flag transition (S/Z/AC/P/CY)
- Edge cases: `DCR` after `80H` (GNUSim8085 #46), `DAA` after `99H+01H` (Phoxis), `ADC` carry propagation (GNUSim8085 #71), `DAD` flag side-effects (sim8085 #45), `SBB` AC flag (sim8085 #44), `CMP` carry flag (jubin #17)

Place at `packages/core-8085/tests/golden/` as JSON files. Loader test iterates them in CI.

### Documentation references
- `packages/core/src/cpu.rs`: step/run pattern, StepRecord, StopReason — copy shape
- `packages/core/src/alu.rs`: ALU flag-update helpers — pattern only (8085 flags differ)
- Intel 8080/8085 Programming Manual: https://nj7p.org/Manuals/PDFs/Intel/9800301D.pdf — authoritative for every flag in every instruction
- GNUSim8085 #71 (adc carry bug): https://github.com/GNUSim8085/GNUSim8085/issues/71 — what NOT to do
- Sim8085 issues #18/#44/#45/#50/#57: confirmed competitor bugs to test against

### Verification checklist
- [ ] `cargo test -p modern8085-core` runs the golden corpus, all pass
- [ ] Each of the 20 example programs from Phase 0.5 executes to HLT with the expected output memory state
- [ ] No `unwrap()` in instruction execution path
- [ ] Cycle budget enforced — passing `budget=100` halts at 100 even for tight infinite loops
- [ ] `proptest` round-trip: random byte sequences never panic the decoder

### Anti-pattern guards
- DO NOT reset AC on `DAD` (sim8085 #45 — only CY changes).
- DO NOT skip parity bit count.
- DO NOT use signed comparison in `CMP` flag computation — it's unsigned, sign-flag derives from the subtraction result high bit only.
- DO NOT panic on undefined opcodes — execute as NOP and log, like real silicon (deterministic, doesn't crash students' programs).

### What to implement

## Dependencies & parallelism

```
Phase 0 (DONE)
  ↓
Phase 1 (skeleton)
  ↓
Phase 2 (core M0) ─┐
  ↓                │
Phase 3 (asm) ─────┼─→ Phase 5 (wasm) ─→ Phase 6 (React) ─→ Phase 7 (examples) ─→ Phase 8 (wire) ─→ Phase 9 (polish) ─→ Phase 10 (catalogue) ─→ Phase 11 (ship)

```

Phases 3 and 4 can run in parallel (assembler doesn't depend on executor; executor doesn't depend on assembler text). Phase 6 (React shell) can begin once Phase 5 ships any working `Emulator` stub — initial pane plumbing doesn't need every instruction implemented.

- Tauri desktop/Android packaging of 8085 (would be a follow-up release, like 8086 v1.1.0 → v1.1.4)

- Undocumented 8085 instructions (DSUB, ARHL, RDEL, LDHI, LDSI, LHLX, RSTV, SHLX) — defer to a v1.x feature ticket
